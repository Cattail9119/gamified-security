# Проєкт
Веб-прототип гейміфікованої платформи навчання безпеці (магістерська). Інтерфейс — українською.

## Обсяг прототипу
- Головна: картки курсів (secure-dev, cyber-hygiene, cryptology активні; cisco — «скоро»), прогрес по курсу
- Сторінка курсу: пронумерований список завдань зі статусами (не розпочато / є спроби / виконано / переглянуто розбір) і XP
- Екран завдання:
  - теоретичний блок першим кроком, якщо в завданні є поле `theory`; далі кнопка «До завдання»
  - умова, робоча зона за типом, кнопки «Перевірити» і «Підказка», розбір після перевірки
- XP, рівень і прогрес у localStorage; кнопка «Скинути прогрес» у шапці

## Правила
- Завдання — це дані (JSON у /content); рушій не знає про конкретні теми
- Типи: multi-choice, find-in-code, text-answer, pick-email (прості, у демо не використовуються) та інтерактивні:
  inbox-triage, scenario, password-lab, injection-sandbox, fill-slots, cipher-lab, hash-check;
  новий тип = новий компонент + функція перевірки
  (файл у `src/tasks/`, тип у `src/types/content.ts`, запис у реєстрі `src/tasks/index.ts`)
- `TaskTypeDef.feedback` (необов'язково) повертає короткий коментар після неправильної спроби, не розкриваючи відповіді
- Без бекенду, реєстрації та сторонніх сервісів
- Стек: React + TypeScript + Vite

## Не робимо зараз
Бекенд, логування експерименту, адмінка, бейджі, рейтинги

# Контент: як додавати курси й завдання

## Курси — `content/courses.json`
Масив об'єктів:

| Поле | Опис |
|---|---|
| `id` | Латиниця й дефіси. Збігається з іменем файлу завдань і входить в URL |
| `title` | Назва на картці |
| `description` | Короткий опис на картці |
| `icon` | Необов'язкове, в інтерфейсі не показується (іконки курсів прибрано) |
| `status` | `"active"` або `"soon"` (картка неактивна) |

## Завдання — `content/tasks/<id-курсу>.json`
Масив завдань. Порядок у файлі = порядок і нумерація на сторінці курсу.
Новий файл підхоплюється автоматично, реєструвати його ніде не треба.

### Спільні поля

| Поле | Обов'язкове | Опис |
|---|---|---|
| `id` | так | Унікальний у межах курсу, латиниця й дефіси. Входить в URL і ключ прогресу — після публікації не змінювати |
| `type` | так | `multi-choice`, `find-in-code`, `text-answer`, `pick-email`, `inbox-triage`, `scenario`, `password-lab`, `injection-sandbox`, `fill-slots`, `cipher-lab`, `hash-check` |
| `title` | так | Назва в списку і на екрані завдання |
| `xp` | так | Скільки XP дає правильна відповідь |
| `theory` | ні | Текст теорії. Якщо є — показується першим кроком, далі кнопка «До завдання» |
| `prompt` | так | Умова завдання |
| `hint` | ні | Підказка. Якщо нема — кнопка «Підказка» не показується |
| `explanation` | так | Розбір: показується після правильної відповіді або якщо користувач здався |

### Формат тексту
Поля `theory`, `prompt`, `hint`, `explanation` і `body` листа — це **рядок або масив рядків**:
- кожен елемент масиву — окремий абзац (у звичайному рядку абзаци розділяються порожнім рядком `\n\n`);
- абзац, у якому кожен рядок починається з `- `, стає маркованим списком;
- `\n` всередині абзацу — перенос рядка;
- всередині тексту: `` `код` `` і `**жирний**`.

### Поля за типом

**`multi-choice`** — вибір варіантів
- `options`: масив рядків;
- `correct`: масив індексів правильних варіантів (рахуються з 0). Один індекс → радіокнопки, кілька → чекбокси. Зараховується лише точний збіг.

**`find-in-code`** — позначити рядки з проблемою
- `code`: масив рядків коду (або один рядок із `\n`);
- `correctLines`: номери рядків, які треба позначити (рахуються **з 1**, як на екрані). Зараховується лише точний збіг.

**`text-answer`** — ввести відповідь
- `answers`: масив прийнятних варіантів. Регістр, пробіли по краях і подвійні пробіли не враховуються;
- `placeholder` (необов'язково): підказка в полі вводу.

**`pick-email`** — обрати один лист серед кількох
- `emails`: масив об'єктів `{ "from": "...", "subject": "...", "body": текст }`;
- `correct`: індекс правильного листа (рахується з 0).

**`inbox-triage`** — розбір пошти (вердикт + позначення ознак)
- `emails`: `{ fromName, fromAddr, subject, body: [абзаци], phishing: true/false, clues: [id] }`;
- у `fromAddr`, `subject`, `body` фрагменти, які можна позначити клацанням, пишуться `[[id|текст]]`,
  посилання з прихованою адресою — `[[id|текст|https://справжня-адреса]]` (адреса видна при наведенні курсора);
- `clues` — id справжніх ознак фішингу; позначувані фрагменти, яких немає в `clues`, — відволікаючі;
- зараховується: усі вердикти вірні, позначені рівно всі `clues` (зайві позначки — помилка).

**`scenario`** — рішення в ситуації з наслідками
- `steps`: `{ title?, situation, choices: [{ text, points, outcome }] }`; наслідок показується одразу після вибору;
- `passScore` — мінімум балів.

**`password-lab`** — створити пароль під умови
- `profile` (рядки профілю), `forbidden` (особисті підрядки), `common` (поширені слова), `minLength`, `minYears`.

**`injection-sandbox`** — симуляція SQL-ін'єкції
- `queryTemplate` з `{login}` і `{password}`; `accept` — регулярні вирази, що перевіряються на готовому запиті.

**`fill-slots`** — вибір у списках, що випадають
- `mode`: `code` (код із пропусками) або `steps` (кроки схеми);
- `template`: рядки з `{{1}}`, `{{2}}`…; `slots`: `{ options, correct }` у тому самому порядку; `diagram` (необов'язково) — схема учасників.

**`cipher-lab`** — підбір ключа шифру Цезаря повзунком
- `ciphertext`, `plaintext` (латиниця).

**`hash-check`** — порівняння SHA-256 файлів
- `files`: `{ name, content: [рядки], sha256 }` (`sha256` — хеш оригіналу), `tampered` — індекси підмінених файлів.

## Правила нарахування
- XP за завдання нараховується один раз — за першу правильну відповідь.
- Після неправильної спроби з'являється «Здатися й показати розбір»: розбір відкривається, XP за завдання не нараховується.
- Рівень = 1 + кожні 100 XP.
- Прогрес зберігається в localStorage під ключем `gamified-security.progress.v1`.
